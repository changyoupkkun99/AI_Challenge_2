# 전원 합의 고정 + 검증 기반 유형별 가중 투표

현재 초기 모델 CSV 10개가 같은 답을 낸 4,444문항을 고정하고, 나머지 2,270문항을 질문 유형에 따른 가중 투표로 결정한다. 기준 제출 파일은 유형 분류, 가중치 산정, 동점 처리에서 읽지 않는다.

## 실행과 결과 보관

solution 폴더에서 실행한다. Python 3.9 이상, 표준 라이브러리만 사용한다.

```bash
python3 앙상블_merge/type_based_ensemble/run.py --seed 42
```

매번 `runs/실행시각_고유번호/`를 새로 만들어 다음 내용을 보관한다. 기존 실행은 덮어쓰지 않는다.

- `submission.csv`: 해당 실행의 6,714행 답안.
- `weights.json`, `type_weights.csv`: 실제 모델별·유형별 가중치와 근거 문항 수.
- `vote_audit.csv`: 초기 모델 10개의 답, 합의 고정 여부, 유형, 가중 합, 최종 답.
- `inputs_snapshot.json`, `settings_snapshot.json`: 입력 해시와 설정.
- `cross_validation.json`, `cross_validation_predictions.csv`: 교차검증 결과와 문항별 예측.
- `verification.json`: 시드, 결과 해시, 처리 건수와 입력 상태.

`runs/history.jsonl`에는 완료한 실행을 계속 추가하고, `runs/latest.json`에는 최신 실행 위치를 기록한다. 시드는 교차검증 폴드와 투표 동점 선택에만 사용한다. 가중치를 무작위로 뽑는 방식은 아니다. 같은 입력·설정·시드에서 같은 CSV와 가중치가 생성되는지 검증했다.

다른 결과 보관 위치를 지정하려면 `--output-dir 경로`를 추가한다.

## 어떤 검증 근거를 사용했는가

다음 네 모델의 저장된 문항별 검증 예측에서 공통으로 존재하는 **공식 train 라벨 1,096문항**을 사용했다.

| 모델 | 해당 공통 문항에서 라벨과 일치 |
|---|---:|
| 종서 Qwen 4B | 1,074 / 1,096 |
| 종서 Qwen 8B | 1,072 / 1,096 |
| 종서 Gemma 26B | 1,087 / 1,096 |
| 종서 Gemma 31B | 1,091 / 1,096 |

네 모델 모두 해당 ID가 각 실행의 검증 목록에 포함되고 학습 목록에는 없음을 확인했다. 예측 파일의 전체 행 수와 정답 일치 수는 각 실행의 저장된 지표와 대조했다. 네 모델의 라벨을 원래 train.csv의 라벨과 확인했으며, dev 의사 라벨은 가중치 산정에서 제외했다.

나머지 초기 모델 6개는 전원 합의 확인에는 참여하지만 유형별 가중 투표에는 참여하지 않는다. 이 실행에서 충분한 규모의 동일 조건 검증 예측을 연결하지 못했기 때문이다. 기존 앙상블· CSV 46개 역시 유형별 검증 예측이 없어 투표 입력에 추가하지 않았다. 검증 근거가 없는 파일에 유형별 정확도를 만들어 부여하지 않는다.

## 질문 유형

질문 문장에 적용하는 사전 정의 정규식으로 분류한다. ID나 기준 제출 답을 분류 규칙에 넣지 않는다. 여러 유형이 겹치면 아래 순서에서 먼저 일치한 유형을 사용한다. 실제 규칙은 `settings.json`에 있다.

| 유형 | 공통 검증 문항 | 테스트 전체 | 합의되지 않아 투표한 문항 |
|---|---:|---:|---:|
| 부정·부재 | 47 | 344 | 247 |
| 수량·크기 비교 | 6 | 50 | 27 |
| 숫자·날짜·연락처 | 247 | 1,504 | 544 |
| 위치·방향 | 79 | 475 | 170 |
| 문자·명칭 읽기 | 424 | 2,686 | 749 |
| 기타 시각 질문 | 293 | 1,655 | 533 |

이는 질문 문장 기반 분류이며, 이미지의 실제 글자 크기나 OCR 품질을 분석한 결과는 아니다. 규칙이 문항의 세부 의도를 완벽하게 분류한다고 보장하지 않는다.

## 가중치 계산

검증 표본이 적은 유형이 극단적인 가중치를 만들지 않도록 모델 전체 정확도 쪽으로 보정한다.

```text
p_global = (전체 일치 수 + 1) / (전체 문항 수 + 2)
p_type   = (유형별 일치 수 + 30 × p_global) / (유형별 문항 수 + 30)
weight   = round(1,000,000 × max(0, ln(3 × p_type / (1 − p_type))))
```

유형별 문항이 30개 미만이면 p_type 대신 p_global을 사용한다. 수량·크기 비교 유형은 6문항뿐이므로 전체 가중치를 사용한다. 문항 수 기준 30과 보정 강도 30은 유형별 결과나 기준 제출과의 차이를 보고 탐색한 값이 아니라, 이번 구현에서 사전에 정한 설정이다.

동점인 최상위 보기만 시드와 ID의 해시로 선택한다. ID는 동점 선택과 기록에만 사용하며, 특정 문항의 답을 지정하지 않는다. 이번 실행에는 실제 투표 동점이 없었다.

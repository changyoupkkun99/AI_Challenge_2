# 기존 결과를 포함한 고정 가중치 가능성 검사

현재 입력인 초기 모델 10개와 기존 앙상블· CSV 46개를 사용해, 모든 문항에 동일한 비음수 가중치를 적용하는 투표로 reference 전체를 만들 수 있는지 검사했다. 이 검사는 사용자가 요청한 목표 파일 일치 가능성 검사이며, reference을 읽어 조건을 만들었다. 기존 병합의 입력·가중치·출력은 변경하지 않았다.

**결과: 현재 56개 입력의 고정 가중치 투표로는 reference과 완전히 일치할 수 없다.** 가중치 일부를 0으로 두거나, 가중치를 실수로 허용하거나, 모든 동점을 reference에 유리하게 처리해도 결론이 같다. 전체 가중치가 0인 경우는 투표로 답을 결정하지 못하므로 제외한다.

## 세 문항으로 확인되는 충돌

56개 파일의 세 문항 예측은 다음 네 가지 패턴뿐이다.

| 파일 수 | 1166번 | 1931번 | 2372번 |
|---:|:---:|:---:|:---:|
| 7 | d | b | a |
| 46 | d | a | a |
| 1 | d | b | c |
| 2 | c | b | a |
| **reference** | **c** | **a** | **c** |

각 입력 파일은 이 세 문항에서 reference과 **최대 한 문항만** 같다. 총 가중치를 `W > 0`이라고 하자.

- 1166번은 c와 d만 나오므로, c가 이기거나 동점이 되려면 c 지지 가중치가 `W/2` 이상이어야 한다.
- 1931번은 a와 b만 나오므로, a 지지 가중치가 `W/2` 이상이어야 한다.
- 2372번은 c와 a만 나오므로, c 지지 가중치가 `W/2` 이상이어야 한다.

세 지지 집합에는 겹치는 파일이 없다. 따라서 세 지지 가중치의 합은 최대 `W`인데, 동시에 reference과 같아지려면 최소 `3W/2`가 필요하다. `W > 0`에서 두 조건은 동시에 성립하지 않는다.

즉 랜덤 가중치를 계속 뽑거나 시드를 바꾸어도, **한 실행에서 전체 문항에 동일하게 적용하는 가중치**로는 이 세 답을 동시에 만들 수 없다.

## 계산과 검증

6,714문항에서 필요한 중복 없는 투표 부등식 1,123개를 만들고 선형계획법으로 해가 없음을 확인했다. 이어 세 부등식의 정수 합으로 모든 입력의 계수가 -1 또는 -3이 되는 모순 증명을 추출했다. 검증 코드는 모델 입력에서 계수를 직접 다시 계산하므로 최적화 도구의 결과만 신뢰할 필요가 없다.

solution 폴더에서 실행:

```bash
python3 앙상블_merge/weight_feasibility_check/verify.py
```

검증에는 Python 표준 라이브러리만 필요하다. 입력 해시, 참조 파일 해시, 세 문항의 실제 답과 정수 부등식 합을 확인한다.

- `certificate.json`: 정수 계수와 입력·참조 해시.
- `conflicting_rows.csv`: 입력 56개 각각의 세 문항 예측.
- `result.json`: 검사 범위와 결과.

## 결론의 범위

이번 검사는 현재 56개 파일과 비음수 고정 가중치 투표에 대한 것이다. 다른 입력 CSV 추가, 문항마다 다른 가중치, 비선형 결합, 원본 수정은 검사 범위 밖이다. 현재 병합의 59개 차이가 최소 차이라는 뜻도 아니다. **정확한 전체 일치가 불가능하다는 것만 증명했다.**
